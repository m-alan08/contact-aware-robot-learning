## 1. Motivation

H1-001 found that an event-triggered refresh of a learned tactile forecast,
made at the moment of an action correction, prevented grasp failures that a
stale forecast and live feedback did not. It could not tell apart three
explanations:

* **(A)** the learned predictor captures dynamics that a simpler method cannot;
* **(B)** any simple, action-aware anticipation would do the same;
* **(C)** the effect is an artifact of the slow simulated gripper or late feedback.

H1-001 also found that it is significant only at m ≥ 0.25 (see the 2026-11-18
erratum). H1-002 tests the three explanations with matched information and
compute.

## 2. Protocol summary

Full details are in the registered protocol.

**Closed-loop conditions.** The same safety controller as H1-001 is used
throughout (`N_min = 1.7 N`, `κ = 7.5`, one-sided live term plus forecast term).

| ID | Condition |
|---|---|
| **A** | cached learned forecast (H1-001 corrected-trained MLP) |
| **B** | refreshed learned forecast (same MLP, event-triggered refresh at `t_c`) |
| **C** | live feedback only |
| **D** | refreshed **analytic** forecast (non-learned; §3.1) |
| **E** | refreshed forecast from an MLP trained **only on uncorrected actions** |
| **O** | oracle: true simulated future; **not deployable**; diagnostic only |

**Grid.**
* Gripper slew per step:
  * 0.03: full stroke 1.67 s, force rise (10–90%) ≈ 350 ms
  * **0.06**: H1-001; 0.83 s; ≈ 150 ms
  * 0.12: 0.42 s; ≈ 50 ms
  * 0.24: 0.21 s; within one 50 ms step
* Tactile sensing latency L ∈ {0, 50, 100, 200 ms}.
* Grip-decrease magnitude m ∈ {0, 0.1, 0.2, 0.3, 0.4}.
* Plus a lift-increase block (m ∈ {0.3, 0.6} × L ∈ {0, 100 ms} at slew 0.06).

That is 84 cells × **150 trials**. Trial seeds `80,000,000 + j` are shared
across all cells, and no seed was skipped in any cell. A, B, and E run with
each of 5 predictor seeds; C, D, and O run once per trial. In total: **226,800
episodes**.

**Statistics.**
* A hierarchical bootstrap (2000 resamples) resamples trial seeds (clusters)
  and predictor seeds; per-seed estimates are kept separately.
* Practical threshold δ = 0.03 absolute success.
* "Challenging" pool: m ∈ {0.2, 0.3, 0.4}.

## 3. Implementation

### 3.1 Analytic anticipation (D) — `src/contact_learning/predictors/analytic.py`

* **Model.**
  * Future applied grip follows from the commanded chunk and the known slew
    limit (actuator specification).
  * Normal force is `N̂ = κ̂ · max(0, ĝ − ĝ0)`.
* **Calibration.** Steady-state grip sweeps on 20 calibration objects (seeds
  `90,000,000+`, disjoint from everything else) gave `κ̂ = 7.49 N` per unit
  grip and `ĝ0_prior = 0.600`, with a residual of 9 mN.
* **Online offset.** `ĝ0` is re-estimated from the latest *available*
  (delayed) measured force and applied grip.
* **No privileged information.** It never reads mass, friction, or simulator
  parameters. A test checks the inputs and the source code.
* Two parameters in total, vs. 157,480 for the MLP.

### 3.2 Nominal-trained predictor (E)

The episode seeds, plans, objects, action noise, architecture, epochs, and
early stopping are identical to the corrected-trained predictor for the same
speed and seed. **Only the random corrections are removed.** The random stream
is consumed identically, which a test verifies. There are 5 seeds per speed.
None met the registered training-failure condition (validation RMSE above
persistence).

### 3.3 Speed-specific predictors

Corrected-trained MLPs were retrained identically at slews 0.03, 0.12, and
0.24. The H1-001 checkpoints are reused read-only at 0.06. In total, 35 new
models were trained in 376 s with 8 parallel workers.

### 3.4 Sensing latency (causal)

* At step t, the controller sees tactile observations only up to `τ = t − L`.
* Forecasters receive the history at τ, including proprioception at τ. They
  predict forward through the actions already executed in `[τ, t)` plus the
  planned chunk, and only predicted steps after t are used.
* The live term uses `N_meas(τ)`.
* A test checks that the forecaster input at `t_c` equals the history built at
  `t_c − L` from an independent rollout.

**Three latencies are recorded separately:**
* sensor latency (L);
* per-forecast inference wall time (median ≈ 0.09–0.11 ms for both the MLP and
  the analytic model, including Python feature construction; oracle ≈ 2.5 ms);
* actuator delay (one 50 ms zero-order-hold step, plus slew).

End-to-end decision latency = L·50 ms + inference + 50 ms.

### 3.5 Speed-aware planner

For slower-than-reference grippers, the lift is delayed by
`ceil(g_hold/slew) − ceil(g_hold/0.06)` steps. Plans at slew ≥ 0.06 are
identical to H1-001 (this is tested). Nominal success with no correction and no
controller was 200/200 at every speed. At slew 0.03, contact starts at steps
23–27, so the only valid correction time is `t_c = 30`, which falls while the
grip is still ramping. This changes the task distribution at that speed.

## 6. Registered decisions

Applied mechanically in `experiments/h1/analyze_h1_002.py`.

| Question | Decision |
|---|---|
| **RQ-a** learned vs. analytic | **Explanation B supported: simple analytic anticipation suffices.** K1 and K2 are both inside ±δ. |
| **RQ-b** corrected training needed? | **Inconclusive** by the registered rule. It is not needed at the H1-001 setting (K3 = −0.006, equivalent). Pooled over all cells it is needed (+0.052). The cost is concentrated at fast grippers with latency (up to +0.25). |
| **RQ-c** latency/actuation artifact? | **Explanation C not supported as registered.** Anticipation helps by +0.09 even with the fastest gripper and zero latency (K4). Its benefit is *smallest* with the *slowest* gripper (+0.02). Sensing latency strongly amplifies it (+0.54 at 200 ms). |

## 7. Interpretation

Each claim below is labelled with its evidential status.

1. **Action-induced forecast mismatch exists.** *Observation, as in H1-001.*
   The cached forecast's normal-force error on the H1-001 trials rises to
   1.47 N for large grip decreases, vs. ~0.2 N refreshed. This holds for the
   analytic model too: any action-conditioned forecaster disagrees with its own
   earlier forecast when the action changes.
2. **A refreshed forecast improves control in this task.** *Statistical
   evidence, across a broad grid.* The improvement holds at every gripper speed
   and latency tested for grip decreases ≥ 0.2. It is small for the slowest
   gripper at zero latency and very large with sensing latency. A stale
   forecast is inert, not harmful (K6).
3. **Learned tactile prediction is not necessary in this task.** *Statistical
   evidence; registered equivalence.* A two-parameter analytic grip→force model
   with the known slew limit matched the learned predictor in every one of the
   16 speed×latency cells (|B − D| ≤ 0.013) and matched the oracle. It is also
   the more accurate forecaster on the H1-001 correction trials (0.099 vs.
   0.113 N), although it is worse on training-style windows that contain
   object-loss events.
   **The learned-forecasting contribution is therefore not established.**
   This follows from a simulated plant whose grip→force map is nearly linear
   and fully observable from proprioception. A real tactile sensor and real
   contact (compliance, slip, deformable objects, unmodelled actuator
   behaviour) could break the analytic model's assumptions. That is untested.
4. **Generalization of the H1-001 result.** *Mixed.*
   * It generalizes across gripper speed and latency, and the benefit grows
     with latency.
   * It does **not** extend to lift-increase corrections, which cause no
     failures here.
   * H1-001's mechanistic reading ("the slow gripper cannot recover in time")
     is **not supported**. The benefit is largest when the correction changes
     contact faster than feedback can react: faster grippers and longer
     sensing delays. A slow gripper slows the harmful force drop as much as the
     recovery.
5. **Training on corrected actions.** *Mixed evidence.* At the H1-001 speed, a
   nominal-trained predictor is as good in closed loop (even slightly better),
   despite worse forecasts for large corrections. At fast grippers with
   latency, it fails badly (e.g. 0.42 vs. 0.93 at slew 0.12, 200 ms, m 0.4).
   *Interpretation:* pessimistic forecast errors cause over-compensation that
   this one-sided controller tolerates. That is why E can even beat the
   oracle (0.952 vs. 0.893 at slew 0.06, 200 ms, m 0.4). **Forecast accuracy
   and control benefit are not the same thing here.** The oracle bounds
   forecast accuracy, not success.

## 8. Limitations

* **Simulation-only, with an idealized contact signal** (net MuJoCo force plus
  noise). The analytic model's success relies on a quasi-static, linear
  grip→force map and a fixed object width. Real tactile sensing and contact
  are unlikely to be this simple.
* **One controller.** It is one-sided, has a fixed `N_min`, and undoes the
  correction. The conclusions are about anticipation *for this controller*.
  The H2 setting (forecasts that can override measurements) is untested.
* **One task and one object shape.** Mass and friction ranges are narrow. The
  correction family is one persistent offset.
* **Speed variation changes the task distribution.** At slew 0.03, only
  `t_c = 30` is valid, during the grip ramp.
* **Inference cost** is negligible for both forecasters here (~0.1 ms). H1-002
  says nothing about settings where forecasting is expensive.
* **Pooled contrasts weight all cells equally.** The decisions rest on the
  registered pools; the cell maps show heterogeneity.
* **Shared trials across cells.** Trial clusters are resampled together, but
  the same 150 objects and plans appear in every cell.

## 9. Recommended next experiment

**Break the analytic model's assumptions** before investing in learned
forecasting:

* object compliance or deformable objects;
* contact geometry varied (object width, rotation);
* friction/mass changes within an episode (H2-style disturbances);
* a more realistic tactile observation (spatial taxel array with filtering and
  bias drift).

Re-run B vs. D under the same registered contrasts. If the learned forecast
only beats an analytic model once the plant has unmodelled contact dynamics,
that defines where a learned-forecasting contribution can exist.

Alternatively, move to **H2 with a forecast-dependent policy**, where a stale
forecast can actually mislead. In H1-001 and H1-002 stale forecasts were inert,
so the "outdated prediction overrides live touch" failure has not yet been
observed.
